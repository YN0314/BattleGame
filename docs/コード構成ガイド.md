# 格闘ゲーム コード構成ガイド

2026-10-21

このゲームは、ブラウザだけで動く素のJavaScript(約4,600行)で、設定・データ・入力基盤・ゲームのルール・描画・画面(シーン)を別々のフォルダに分け、上の層だけが下の層を知る一方向の構造になっている。

## 1. 全体像:6つの層

依存は表の下から上へだけ向かう。上の層は下の層を呼べるが、下の層は上の層を知らない。特に「game(ルール)」は「render(描画)」を知らないので、見た目を変えても判定は変わらない。

| 層(フォルダ) | 役割 | 知っているもの |
| --- | --- | --- |
| scenes | 画面ごとの進行(タイトル、対戦) | 下のすべて |
| render | 状態を読んで画面に描くだけ | game, data, config |
| game | キャラの動き、判定、飛び道具、CPU | core, data, config |
| core | 入力、ゲームループ、画面切替、音 | config |
| data | スプライト生成、配色 | config |
| config | 調整値の置き場(数値だけ) | なし |

すべて `window.Game` という1つの名前空間にぶらさがる(`Game.Config` / `Game.Data` / `Game.Core` / `Game.Logic` / `Game.Render` / `Game.Scenes`)。`<script>` を `index.html` に並べる順番が依存の順番そのもので、ビルド不要・`index.html` のダブルクリックで動く。

## 3. 起動と1フレームの処理フロー

1. `main.js` が入力、デバッグ、音、描画を初期化し、`Sprites.preload()` でドット絵を先に作り、タイトル画面へ移る。
2. `Loop.start` が `requestAnimationFrame` で回り続ける。更新は時間をためて1/60秒ずつ `update` を呼ぶ(処理落ちしても進み方は一定。1回に進める上限は250ms)。
3. 更新のあと、その時点の状態を `render` で1回描く。描画は更新の回数とは独立。
4. `update` / `render` は `SceneManager` が現在の画面(タイトルか対戦)に渡す。画面は `enter(params)` / `update()` / `render()` を持つオブジェクトで、`SM.go('battle', {mode, level})` で切り替わる。

タイトル → モード選択(VS 2P / VS CPU)→ CPUならレベル選択 → 対戦 → 結果メニュー(REMATCH / TITLE)の順に進む。

## 4. 対戦中の1コマ

`scenes/battle.js` の `update()` が中心。ラウンドの進行(phase)は intro → fight → ko → (次ラウンドのintro / 試合終了なら result)。fight のときだけ操作と当たり判定が動く。

1. ヒットストップ中なら何も進めず戻る(入力の読み取りも止めて、止まっている間の押下を失わない)。
2. `Input.update()` がキーボードとパッドを論理入力(押している間 / 押した瞬間)に直し、`InputHistory` へ記録する。
3. `inputFor(i)` が入力を決める。CPU対戦の2Pは `Brain.think()` が同じ形の入力を作る。
4. `stepWorld` が世界を1コマ進める:
    1. 2人の `Fighter.update(input, opponent)` を呼ぶ(歩き・ジャンプ・攻撃・必殺技・投げ・やられを状態機械で処理)。
    2. 技の出し始の音、投げ抜け、ため完了の合図、超必殺技の発動演出を拾う。
    3. `Physics.separate` で二人の重なりを押し戻し、画面端では攻撃側を押し返す。
    4. `Projectile.update()` で飛び道具を進める。
    5. fight のときだけ、`Combat.resolve`(近接技)→ `Projectile.resolve`(飛び道具)→ 投げの順に当たり判定し、結果ごとにヒットストップ、火花、横揺れ、効果音、ゲージ加算を行う。
5. 体力0なら `endRound('ko')`、時間切れなら `endRound('time')`。勝ち数が先取数に到達していれば結果画面へ。

描画は別の流れで、`Renderer.draw` が「背景 → キャラ(影・スプライト)→ 飛び道具 → エフェクト → UI(体力・ゲージ・タイマー・バナー)」の順に重ねる。UI だけは画面揺れの影響を受けない。

## 5. 主要な仕組み

| 仕組み | 考え方 | 触る場所 |
| --- | --- | --- |
| 技とキャラの分離 | 技は `Config.moves` のライブラリに置き、キャラは「ボタン欄→ライブラリの技名」と必殺技の優先順、体型を指定する。`Character.get(id)` が合成して `Fighter.char` に持たせる | moves.config.js, characters.config.js, game/character.js |
| コマンド入力 | 方向をテンキー番号で履歴に記録し、向きに対する相対値に直して照合。波動拳などのなぞるコマンドと、しばらく押し続けて離す「ため」コマンドの2種類 | input.config.js, core/inputHistory.js |
| 投げ | P+K同時押しで発動。近接コマンド投げ(叩きつけ)も同じ処理。投げ抜けはつかまれた直後の P+K | fighter.js(`tryThrow` / `beginThrow` / `updateThrow` / `techThrow`) |
| 必殺技ゲージ | 当てる・ガードされる・受けるでたまり、ラウンドをまたいで持ち越す。超必殺技は `cost` を消費し、発動時に世界を止めて演出 | game.config.js(`meter`)、battle.js(`gainMeter` / `startFlash`) |
| スプライト | ポーズは関節位置で定義し、腕と脚の曲がりをIKで計算して、自前のラスタライザでドットにする。ポーズ・コマ・配色ごとに1回だけ作ってキャッシュ。輪郭線の太さは pixelScale に連動 | data/sprites.js |
| 高解像度描画 | 論理座標(384×224)はそのままで、キャンバスを pixelScale 倍にして拡大変換をかけて描く。背景・文字・エフェクト・UIもこの細かさで描く | display.config.js, renderer.js, font.js |
| CPU | 人間と同じ形の入力 `{held, pressed, special}` を返すだけ。状況(距離、相手の攻撃)から行動を選び、必殺技は種別(飛び道具・対空・投げ・超必殺)で選ぶ。強さは設定値のみ | game/ai.js, ai.config.js |
| 音 | 音源ファイルなし。Web Audio で波形を合成。最初の入力で有効化し、Mキーでミュート | core/sound.js, sound.config.js |

キャラの状態は idle / walk / jump / crouch / attack / jumpattack / special / landing / hitstun / blockstun / down / getup / ko / throwing / thrown の15種類。`Fighter.update` の先頭の `switch` で分岐する。

## 6. 拡張のしかた

| やりたいこと | 触る場所 |
| --- | --- |
| 数値の調整(ダメージ・発生フレーム・ゲージ量・CPUの強さ) | `js/config/*.config.js` を変えてリロード。コードは触らない |
| 既存の技を別キャラに使わせる | `characters.config.js` にキャラを足し、`normals` と `specials` で技名を割り当てる。`order` に追記 |
| 新しい技を作る | `moves.config.js` に技を足し、コマンドがある技は `input.config.js` に入力列を足す。新しい見た目は `sprites.js` にポーズを足す(技の `pose` で他のポーズを使い回しもできる) |
| キャラごとの違い(体型・速さ・技の上書き) | `body` と `overrides`(キャラ定義内) |
| キャラ選択画面を入れる | `scenes/` に新しい画面を足して `register`。選んだ id を `SM.go('battle', {chars:[...]})` で渡すと、対戦側はすでに受け取る作りになっている |
| 見た目を変える(背景・色・表示) | `render/` と `data/` だけ。ルール側のファイルは変更不要 |
| 新しいスクリプトを足す | `index.html` の `<script>` を、依存する層より後ろに足す |

現状の制約と今後:キャラは hero 1人だけ(約7人分のひな形は未作成)、キャラ選択画面は未実装、見た目は全キャラ共通の仮絵、という状態。詳しい今後の計画は設計書(`docs/`)の11bを参照。
