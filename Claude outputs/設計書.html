2D格闘ゲーム 設計書(v0.1)

ブラウザ単体で動く2D格闘ゲーム。キーボードとUSBコントローラーに対応する。

1. 概要

項目 内容
形式 HTML + JavaScript(Canvas)、単一HTMLファイル
実行環境 Chrome / Edge / Firefox など主要ブラウザ(インストール不要)
入力 キーボード、USBコントローラー(Gamepad API)
モード 1P vs 2P(同一PC)、1P vs CPU
キャラクター 1種類(1P・2Pはパレット違い)
ステージ 1つ(夜の街)
見た目 ドット絵風(低解像度で描画して拡大表示)

スコープ外(将来の拡張)

  • キャラ・ステージの追加
  • 必殺技ゲージ、投げ技、強弱の打ち分け
  • ボタン設定画面(最初は固定配置)
  • オンライン対戦

2. 画面・描画

  • ゲーム内の座標系は 384×224(判定や物理はこの単位)。キャラや画面は pixelScale(既定2)倍の細かさで描き、整数倍で拡大表示して image-rendering: pixelated でドットをぼかさない。
  • 描画順は、背景、キャラ、エフェクト、UI(体力ゲージ・タイマー)。
  • キャラは関節の位置(頭・胸・腰・手・足首)でポーズを定義し、腕と脚の曲がりをIKで計算して1ドットずつ描き出す(js/data/sprites.js)。配色はパレットで差し替える。画像ファイルへの差し替えも可能な構造にする。
  • 1P・2Pはパレットの置き換えで色違いにする。

3. ゲームループ

60fps固定。1フレームごとに次の順で処理する。

  1. 入力の取得(キーボード、ゲームパッド)
  2. 入力履歴の更新(コマンド判定用)
  3. キャラの状態更新
  4. 飛び道具の更新
  5. 当たり判定とダメージ処理
  6. ヒットストップ、画面揺れなどの演出更新
  7. 描画

4. キャラクター設計

4.1 ステータス

項目 値(初期案)
体力 100
歩行速度 1.5 px/frame
ジャンプ 初速 -7、重力 0.35
当たり箱(立ち) 幅24 × 高さ48
当たり箱(しゃがみ) 幅24 × 高さ32

4.2 状態(ステートマシン)

状態 説明 遷移先
idle 待機 walk, jump, crouch, attack, guard
walk 前後歩き idle, jump, attack
jump ジャンプ中 idle(着地), 空中攻撃
crouch しゃがみ idle, しゃがみ攻撃
guard ガード(後ろ入力) idle
attack 攻撃(発生・持続・硬直) idle
special 必殺技 idle
hitstun のけぞり idle, down
down ダウン getup
getup 起き上がり idle
ko 敗北 -

4.3 通常技(フレームデータ初期案)

技 発生 持続 硬直 ダメージ 備考
立ちパンチ 4 3 8 5 速い
立ちキック 7 4 12 8 リーチ長め
しゃがみパンチ 5 3 8 4 下段ではない
しゃがみキック 7 4 14 6 下段(立ちガード不可)
ジャンプパンチ 5 6 着地まで 6 中段(しゃがみガード不可)
ジャンプキック 6 8 着地まで 8 中段

発生 = 攻撃判定が出るまでのフレーム数、持続 = 判定が出ている期間、硬直 = 判定消失後に動けない期間。

4.4 必殺技

技 コマンド 内容 ダメージ
波動拳風(飛び道具) ↓↘→ + P 前方に飛び道具を発射。同時に1発まで 10
昇竜拳風(対空) →↓↘ + P 上昇しながら攻撃。出始め無敵あり、外すと大きな硬直 14
  • コマンド受付は直近18フレーム(0.3秒)以内。
  • 方向入力は「向き」を基準に左右反転して扱う(相手が左にいる場合は←がターゲット方向)。
  • 通常技より必殺技を優先して判定する。

4.5 実装済みの挙動(ステップ2時点)

  • 技は立ち・しゃがみ(↓を押しながら)・ジャンプ中の各パンチ/キックの6種。ジャンプ中の攻撃は1回のジャンプで1回まで。
  • 攻撃判定は技の持続中だけ有効。1回の技は1回しか当たらない。
  • 立ちパンチは高い位置を打つため、しゃがんでいる相手には当たらない。
  • ダウン・起き上がり・KO中は無敵。空中で受けた攻撃と、体力が0になる一撃は吹き飛んで倒れる。
  • 両者の攻撃が同じフレームで当たった場合は相打ちになる。
  • 画面端でのけぞった側が動けない分は、攻撃側が押し返される。
  • 体力が0になると「KO!」を表示し、少し待ってから Enter(コントローラーはStart)で再戦。
  • H キーで、喰らい判定(青)と攻撃判定(赤)の箱を表示できる。技の調整時に使う。
  • 技の数値は js/config/moves.config.js、のけぞりや倒れ方は js/config/physics.config.js で変更する。

5. 当たり判定とダメージ

  • 判定は2種類。喰らい判定は常に体に付く。攻撃判定は技の持続中のみ有効。
  • 攻撃判定と喰らい判定の矩形が重なったらヒット。
  • 1回の技が同じ相手に複数回ヒットしないよう、ヒット済みフラグを管理する。
  • ヒット時はヒットストップ(約6フレーム)、のけぞり、ノックバックを与える。
  • ガード時はダメージ軽減(0)、ガード硬直、ノックバック小。
  • 画面端では、攻撃を受けた側が押し込まれる代わりに、攻撃側が少し後退する。

6. 入力設計

6.1 論理入力

物理入力を一度「論理入力」に変換して、ゲーム側は論理入力だけを見る。

up / down / left / right / punch / kick

6.2 キーボード割り当て(初期)

操作 1P 2P
移動 W A S D ↑ ← ↓ →
パンチ F K
キック G L
決定/開始 Enter -

6.3 コントローラー(Gamepad API)

操作 割り当て(標準配置)
移動 十字キー または 左スティック
パンチ 左ボタン(Xbox: X / PS: □)
キック 下ボタン(Xbox: A / PS: ×)
開始 Start
  • 接続した順に1P、2Pへ割り当てる。キーボードとの併用も可。
  • ブラウザの仕様で、接続後に一度ボタンを押すまで認識されない。タイトル画面で「ボタンを押してください」と案内する。
  • スティックは約0.5のしきい値でデジタル化する。

6.4 入力履歴

  • 毎フレームの入力状態をリングバッファに保存する(直近60フレーム)。
  • 方向入力は8方向(テンキー表記 1〜9)に正規化して、コマンド判定に使う。

7. CPU

レベル 挙動
弱い 距離に応じて近づく・離れる、時々パンチ。ガードはほぼしない
普通 間合い管理、対空の昇竜拳、飛び道具、ガードを行う

CPUも論理入力を生成する形で実装し、プレイヤーと同じ操作系を通す。

8. ゲーム進行

8.1 画面遷移

タイトル → (モード選択) → ラウンド開始演出 → 対戦 → 勝敗表示 → 次ラウンド or 結果 → 再戦/タイトル

8.2 ルール

  • 2本先取
  • 制限時間60秒。時間切れは残り体力の多い方が勝ち(同じならドロー=両者1本)
  • ラウンド開始時に「ROUND n / FIGHT!」を表示
  • KO時にスローモーション演出

9. 演出・サウンド

  • ヒットストップ、画面揺れ、ヒット火花
  • 効果音はWeb Audio APIで生成する(パンチ、キック、ヒット、ガード、必殺技、KO)。音声ファイル不要。
  • BGMは最初は無し。必要なら後から追加。

10. コード構成(複数ファイル)

10.1 読み込み方式

通常の <script> タグで読み込む。index.html をダブルクリックするだけで動かすため、ES Modules は使わない。全ファイルは共通の名前空間 Game にぶら下げ、読み込み順は index.html に書く(動きの滑らかさは方式によらず変わらない)。

10.2 フォルダ構成

ゲーム/
├─ index.html
├─ css/style.css
├─ docs/設計書.md / 設計書.html
└─ js/
    ├─ namespace.js        名前空間 Game の定義
    ├─ main.js             起動
    ├─ config/             調整用の数値(ロジックに数値を直書きしない)
    │   ├─ game.config.js      fps、ラウンド数、制限時間、体力
    │   ├─ physics.config.js   歩行速度、ジャンプ、重力、体の大きさ
    │   ├─ moves.config.js     技のフレームデータ、ダメージ(ステップ2〜)
    │   ├─ input.config.js     キー・パッド割り当て、しきい値、履歴フレーム数
    │   ├─ ai.config.js        CPUの強さ(ステップ5)
    │   └─ display.config.js   解像度、拡大倍率、アニメ速度、デバッグ表示
    ├─ data/               素材データ(ロジックなし)
    │   ├─ palettes.js         1P/2Pの配色
    │   └─ sprites.js          ドット絵(仮)
    ├─ core/               ゲームに依存しない基盤
    │   ├─ input.js            キーボード・パッド → 論理入力
    │   ├─ loop.js             固定タイムステップのループ
    │   ├─ debug.js            デバッグ表示
    │   ├─ inputHistory.js     入力履歴、コマンド判定(ステップ4)
    │   └─ sound.js            効果音(ステップ5)
    ├─ game/               ゲームのルール(描画に触れない)
    │   ├─ fighter.js          状態機械、移動
    │   ├─ physics.js          押し合い
    │   ├─ combat.js           当たり判定、ダメージ(ステップ2)
    │   ├─ projectile.js       飛び道具(ステップ4)
    │   └─ ai.js               CPU(ステップ5)
    ├─ render/             描画(状態を読むだけ)
    │   ├─ background.js       ステージ背景
    │   ├─ renderer.js         キャラ描画、拡大表示
    │   ├─ ui.js               体力ゲージ、タイマー(ステップ2〜)
    │   └─ effects.js          火花、画面揺れ(ステップ2〜)
    └─ scenes/             画面ごとの流れ
        ├─ battle.js           対戦
        ├─ title.js            タイトル(ステップ5)
        └─ result.js           結果(ステップ5)

10.3 依存の向き

config / data ← core ← game ← scenes ← main。render は game の状態を読むだけで、game は render を知らない。ルールと見た目を分けることで、ドット絵の差し替えや演出の追加が判定に影響しない。

10.4 設定ファイルの方針

  • 数値(フレーム数、速度、ダメージ、ラウンド数、制限時間など)は config/ にだけ書き、ロジックは Game.Config.xxx を参照する。
  • file:// ではJSONを読み込めないため、設定は .js ファイルに書く。
  • ゲーム内部の時間は「フレーム」。人が読む項目(制限時間など)だけ「秒」で書き、起動時にフレームへ変換する。
  • 変更後はブラウザのリロードだけで反映される。

11. 実装ステップ

段階 内容 確認ポイント
1(完了) 画面表示、キャラの歩行・ジャンプ・しゃがみ(キーボード+パッド)。2体表示、押し合い 動きの気持ちよさ
2(完了) 通常技6種、当たり判定、ダメージ、のけぞり・ダウン、ヒットストップ、体力ゲージ、KO・再戦 攻撃の手触り
3 2体目、ガード、のけぞり、ダウン 対戦として成立するか
4 必殺技(コマンド入力、飛び道具、昇竜) コマンドの出しやすさ
5 ラウンド制、タイトル、CPU、効果音 ゲームとして遊べるか

各段階で動作する版を渡し、触って調整する。

12. リスクと対策

リスク 対策
キーボードの同時押し制限(2人対戦) コントローラー使用を推奨。キー割り当てを離す
コントローラーのボタン配置が機種で異なる 標準配置を基準にし、問題があれば割り当て調整(将来、設定画面)
実機での動作確認が開発側でできない 利用者に試してもらい、フィードバックで調整
操作の入力遅延 requestAnimationFrameと固定タイムステップ、入力は毎フレーム読み取り
ドット絵の品質 仮絵で動かし、素材は差し替え可能にする
