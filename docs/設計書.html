2D格闘ゲーム 設計書(v0.1)

ブラウザ単体で動く2D格闘ゲーム。キーボードとUSBコントローラーに対応する。

1. 概要

項目 内容
形式 HTML + JavaScript(Canvas)、単一HTMLファイル
実行環境 Chrome / Edge / Firefox など主要ブラウザ(インストール不要)
入力 キーボード、USBコントローラー(Gamepad API)
モード 1P vs 2P(同一PC)、1P vs CPU
キャラクター 1種類(1P・2Pはパレット違い)
ステージ 1つ(夜の街)
見た目 ドット絵風(低解像度で描画して拡大表示)

スコープ外(将来の拡張)

  • キャラ・ステージの追加
  • 必殺技ゲージ、投げ技、強弱の打ち分け
  • ボタン設定画面(最初は固定配置)
  • オンライン対戦

2. 画面・描画

  • ゲーム内の座標系は 384×224(判定や物理はこの単位)。キャラや画面は pixelScale(既定4)倍の細かさで描く。ウィンドウに収まらないときは縮小して表示し、整数倍のときだけ image-rendering: pixelated を使う。詳細は 11b.5。
  • 描画順は、背景、キャラ、エフェクト、UI(体力ゲージ・タイマー)。
  • キャラは関節の位置(頭・胸・腰・手・足首)でポーズを定義し、腕と脚の曲がりをIKで計算して1ドットずつ描き出す(js/data/sprites.js)。配色はパレットで差し替える。画像ファイルへの差し替えも可能な構造にする。
  • 1P・2Pはパレットの置き換えで色違いにする。

3. ゲームループ

60fps固定。1フレームごとに次の順で処理する。

  1. 入力の取得(キーボード、ゲームパッド)
  2. 入力履歴の更新(コマンド判定用)
  3. キャラの状態更新
  4. 飛び道具の更新
  5. 当たり判定とダメージ処理
  6. ヒットストップ、画面揺れなどの演出更新
  7. 描画

4. キャラクター設計

4.1 ステータス

ジャンプ 初速 -7、重力 0.35
当たり箱(立ち) 幅24 × 高さ48

4.2 状態(ステートマシン)

状態 説明 遷移先

4.3 通常技(フレームデータ初期案)

技 発生 持続 硬直 ダメージ 備考
立ちパンチ 4 3 8 5 速い
立ちキック 7 4 12 8 リーチ長め
しゃがみパンチ 5 3 8 4 下段ではない
しゃがみキック 7 4 14 6 下段(立ちガード不可)。当たるとダウン
ジャンプパンチ 5 6 着地まで 6 上段(しゃがみガード不可)
ジャンプキック 6 8 着地まで 8 上段(しゃがみガード不可)

発生 = 攻撃判定が出るまでのフレーム数、持続 = 判定が出ている期間、硬直 = 判定消失後に動けない期間。

4.4 必殺技

技 コマンド 内容 ダメージ
波動拳風(飛び道具) ↓↘→ + P 前方に飛び道具を発射。同時に1発まで 10
昇竜拳風(対空) →↓↘ + P 上昇しながら攻撃。出始め無敵あり、外すと大きな硬直 14
  • コマンド受付は直近18フレーム(0.3秒)以内。
  • 方向入力は「向き」を基準に左右反転して扱う(相手が左にいる場合は←がターゲット方向)。
  • 通常技より必殺技を優先して判定する。同時に成立する場合は昇竜拳風が優先される。

4.5 実装済みの挙動(ステップ2時点)

  • 技は立ち・しゃがみ(↓を押しながら)・ジャンプ中の各パンチ/キックの6種。ジャンプ中の攻撃は1回のジャンプで1回まで。
  • 攻撃判定は技の持続中だけ有効。1回の技は1回しか当たらない。
  • 立ちパンチは高い位置を打つため、しゃがんでいる相手には当たらない。
  • ダウン・起き上がり・KO中は無敵。空中で受けた攻撃と、体力が0になる一撃は吹き飛んで倒れる。
  • 両者の攻撃が同じフレームで当たった場合は相打ちになる。
  • 画面端でのけぞった側が動けない分は、攻撃側が押し返される。
  • 体力が0になると「KO!」を表示し、少し待ってから Enter(コントローラーはStart)で再戦。
  • H キーで、喰らい判定(青)と攻撃判定(赤)の箱を表示できる。技の調整時に使う。
  • 技の数値は js/config/moves.config.js、のけぞりや倒れ方は js/config/physics.config.js で変更する。

4.6 ガード(ステップ3で実装)

  • 攻撃を受けた瞬間に、相手と反対の方向(後ろ)を押していればガードになる。ガード専用のボタンや構えはない(押していれば後ろへ歩く)。
  • 地上で、待機・歩き・しゃがみ・ガード硬直中のときだけガードできる。攻撃中、のけぞり中、空中ではできない。
  • 技の高さ(level)とガードの組み合わせ:
技の高さ 立ちガード しゃがみガード(↓+後ろ) 該当する技
上段(high) 防げる 防げない ジャンプパンチ・ジャンプキック
中段(mid) 防げる 防げる 立ち・しゃがみのパンチ、立ちキック
下段(low) 防げない 防げる しゃがみキック
  • ガードするとダメージは0。技ごとのガード硬直(blockstun)と押され方(blockKnockback)がかかる。ヒットストップはヒット時より2フレーム短い。画面は揺れず、青白い火花が出る。
  • ガード中に壁際で押されて動けない分は、攻撃側が押し返される。
  • しゃがみキックは、ガードされなければ相手をダウンさせる(knockdown)。

4.7 必殺技の実装内容(ステップ4で実装)

  • 出し方:コマンドを入力したあと、パンチを押す。方向は相手の方を向いた向きで読む(相手が左にいるときは「前」が左)。
  • コマンドは入力履歴(直近60フレーム)から判定する。コマンド全体は18フレーム以内、最後の方向からパンチまでは8フレーム以内。数値は input.config.js の commands。
  • 波動拳風は ↓↘→+パンチ。キーボードで斜めを入れにくいため、↓→+パンチでも出る。発生12フレーム(この時点で飛び道具が出る)、そのあと22フレーム動けない。
  • 飛び道具は秒速約190px(3.2px/フレーム)で直進し、相手に当たる・ガードされる・画面外へ出ると消える。
  • 同じプレイヤーの飛び道具は同時に1発まで。出ている間は波動拳風は出せない。
  • 相手の飛び道具とぶつかると、互いに消える(相殺)。ジャンプで飛び越えられる。
  • 中段扱いで、立ちでもしゃがみでもガードできる。ダメージ10。
  • 昇竜拳風は →↓↘+パンチ。発生3フレームで飛び上がり、出始めの6フレームは無敵。上昇中の10フレームに攻撃判定があり、当たるとダメージ14でダウンを奪う。
  • 外す、またはガードされると、着地後に24フレーム動けない。
  • 中段扱いで、ガードできる。
  • 必殺技は地上の待機・歩き・しゃがみ中から出せる(通常技のキャンセルは未対応)。
  • 画面下のデバッグ欄に「直近の入力」を相対テンキーで表示する。コマンドが入りにくいときの確認に使う。
  • 技の数値は moves.config.js(fireball / uppercut)で変更する。

5. 当たり判定とダメージ

  • 判定は2種類。喰らい判定は常に体に付く。攻撃判定は技の持続中のみ有効。
  • 攻撃判定と喰らい判定の矩形が重なったらヒット。
  • 1回の技が同じ相手に複数回ヒットしないよう、ヒット済みフラグを管理する。
  • ヒット時はヒットストップ(約6フレーム)、のけぞり、ノックバックを与える。
  • ガード時はダメージ軽減(0)、ガード硬直、ノックバック小。
  • 画面端では、攻撃を受けた側が押し込まれる代わりに、攻撃側が少し後退する。

8. ゲーム進行

8.1 画面遷移

タイトル → (モード選択) → ラウンド開始演出 → 対戦 → 勝敗表示 → 次ラウンド or 結果 → 再戦/タイトル

8.2 ルール

  • 2本先取
  • 制限時間60秒。時間切れは残り体力の多い方が勝ち(同じならドロー=両者1本)
  • ラウンド開始時に「ROUND n / FIGHT!」を表示
  • KO時にスローモーション演出

9. 演出・サウンド

  • ヒットストップ、画面揺れ、ヒット火花
  • 効果音はWeb Audio APIで生成する(パンチ、キック、ヒット、ガード、必殺技、KO)。音声ファイル不要。
  • BGMは最初は無し。必要なら後から追加。

10. コード構成(複数ファイル)

10.1 読み込み方式

通常の <script> タグで読み込む。index.html をダブルクリックするだけで動かすため、ES Modules は使わない。全ファイルは共通の名前空間 Game にぶら下げ、読み込み順は index.html に書く(動きの滑らかさは方式によらず変わらない)。

10.3 依存の向き

config / data ← core ← game ← scenes ← main。render は game の状態を読むだけで、game は render を知らない。ルールと見た目を分けることで、ドット絵の差し替えや演出の追加が判定に影響しない。

10.4 設定ファイルの方針

  • 数値(フレーム数、速度、ダメージ、ラウンド数、制限時間など)は config/ にだけ書き、ロジックは Game.Config.xxx を参照する。
  • file:// ではJSONを読み込めないため、設定は .js ファイルに書く。
  • ゲーム内部の時間は「フレーム」。人が読む項目(制限時間など)だけ「秒」で書き、起動時にフレームへ変換する。
  • 変更後はブラウザのリロードだけで反映される。

11.1 ステップ5a の実装内容

  • シーン:title → battle → (結果メニュー)→ battle(もう一度)/ title。切り替えは Game.Core.SceneManager.go(名前, 引数)。
  • タイトル:最初に「PRESS ENTER OR START」(Enter・Start・パンチ・キックのどれでも可)→ モード選択(VS 2P / VS CPU)。CPUは5bで有効になるまで選べない。↑↓で選択、Enterまたはパンチで決定、キックで戻る。
  • ラウンド進行:intro(ROUND n → FIGHT!、操作不可)→ fight → ko(KO! / TIME UP、前半はスローモーション)→ 次のラウンド or result。
  • 勝敗:体力0でKO。時間切れは体力が多い方の勝ち、同じなら引き分け(両者に1勝)。2本先取で試合終了。両者が同時に先取した場合は DRAW。
  • 画面表示:中央上に残り秒数(10秒以下で赤く点滅)、その下に勝ち数のしるし。
  • 結果メニュー:「REMATCH」(最初から)/「TITLE」。誤操作防止のため表示から約0.75秒は受け付けない。
  • 調整できる値(game.config.js の round):winsToTake, timeLimitSec, introFrames, roundCallFrames, koFrames, koSlowFrames, koSlowRate, resultLockFrames。

11.2 ステップ5b の実装内容

  • CPU(game/ai.js):2P側の入力を、プレイヤーと同じ形(held / pressed)で毎フレーム作る。ボタン入力以外の特別扱いはなく、キャラの動き・当たり判定・ガードはプレイヤーと同じルール。
  • 必殺技:コマンドを再現せず、技名を input.special で直接渡す(Fighter.detectSpecial が受け取る)。飛び道具の同時1発の制限は同じ。
  • 行動:間合い(近・中・遠)ごとに行動を選ぶ。近い=通常技/後退、中=接近・キック・波動拳、遠い=波動拳・ジャンプ・接近。ジャンプで近づく相手には昇竜拳。
  • 防御:相手の攻撃や飛び道具が見えてから「反応遅れ」だけ待って、確率でガード(下段にはしゃがみガード)。
  • 強さ:タイトルで VS CPU を選ぶと EASY / NORMAL を選択。数値は config/ai.config.js(reaction, blockChance, aggression, attackChance, fireball, uppercut, jump, idleFrames, 間合い)。
  • CPU対戦中、2Pのキーボード・パッドは使われない。

11.3 ステップ5c の実装内容

  • 方式:音声ファイルは使わず、Web Audio API で合成(core/sound.js)。素材の用意やライセンスの心配がなく、数値で調整できる。
  • 音の種類:通常技の素振り、ヒット(弱・強)、ガード、波動拳、昇竜拳、KO、メニュー(移動・決定・戻る)、ラウンド開始(ROUND / FIGHT)、時間切れ、試合終了。BGMはなし。
  • 鳴るタイミング:技の出始め(技が切り替わった瞬間を battle.js が見張る)、攻撃がヒット/ガードされた瞬間、ラウンドの進行、メニュー操作。
  • ブラウザの決まり:操作の前に音は出せないため、最初のキー入力・クリック・パッド操作で音を有効にする(タイトルの「ボタンを押してください」がその役目)。
  • 設定(config/sound.config.js):enabled(無音)、master(全体音量)、volumes(音ごとの倍率)。ゲーム中は M キーで消音/解除。

11b. キャラクターと技の分離(キャラ拡張 第1段階)

8キャラ化に向けて、「技」と「キャラ」を分けた。

  • 技ライブラリ(moves.config.js):すべての技を名前付きで登録。必殺技には command(input.config.js のコマンド名)を持たせる。
  • キャラ定義(characters.config.js):キャラごとに次を書く。
  • normals:通常技の枠(standPunch など。ポーズ名と同じ)→ 技ライブラリの技名
  • specials:使える必殺技(優先順)
  • body:体の数値の上書き(歩く速さ、ジャンプ、体力判定の大きさなど。書かなければ共通値)
  • overrides:技の数値の上書き(同じ技でもこのキャラだけ威力を変える等)
  • 合成(game/character.js):定義とライブラリを合成して、キャラごとの技データを作る。Fighter は char.moves を参照する。
  • CPU:必殺技を技名でなく種類(飛び道具・対空)で選ぶため、キャラが違っても使える。
  • 今は hero 1キャラのみ。新キャラは characters.config.js に定義を足すだけで技の組み合わせを変えられる(見た目の追加は次の段階)。
  • 第1段階では、見た目・操作・技の性能は従来と同じ(動作確認済み)。

次の段階:ため技・投げ技の追加(下記)→ 2体目以降のキャラ追加(見た目・キャラ選択)→ 8キャラへ。

11b.1 技のバリエーション追加(ため技・投げ技)

技ライブラリに次の3技を追加し、hero に割り当てた。

技 入力 内容
ソニックブーム風(sonic) 後ろを約0.6秒(36フレーム)押し続け → 前+パンチ 速くて小さい飛び道具(ダメージ7)。出したあとの隙は大きめ。飛び道具は同時に1発まで
サマーソルト風(flashkick) 下を約0.6秒押し続け → 上+キック 後ろへ跳びながら蹴り上げる(ダメージ12・ダウンを奪う)。着地硬直あり
投げ(throw) 近づいて パンチ+キック同時押し ガード中の相手にも成立(ダメージ12・ダウン)。地上の相手のみ、距離32以内のみ
  • ため判定(inputHistory.js):解放の方向を入れた直前に、ためる方向が chargeFrames 以上続いていれば成立。ためと解放の間の途切れは gap フレームまで許す(キーボードでの切り替え用)。設定は input.config.js の sonic / flashkick。
  • ↑解放のため技:↑を押した瞬間にジャンプしてしまわないよう、ため技が出せる状態のときだけ、ジャンプを最大6フレーム待ってキックを受け付ける。
  • 投げ:パンチとキックのどちらかを押した瞬間にもう一方を押していれば成立。通常技の出始め(throwWindowFrames = 3フレーム)なら、押しのずれを許して投げに切り替える。投げられた側は専用状態(thrown)で動けず、投げる側が hitFrame で投げ飛ばす。
  • 技データの新項目:button(出すボタン)、pose(使うポーズ名)、throw(投げ技フラグ、range/grabDist/hitFrame/frames)。
  • CPU:飛び道具・対空は「使える技から種類で選ぶ」ので新技も使う。近距離では throw の確率で投げを狙う(ai.config.js)。
  • ため完了の表示と投げ抜けは 11b.4 で実装。

11b.2 キャラ特有のコマンド投げ「叩きつけ」(slam)

  • 入力:←↙↓↘→(半回転)+パンチ。キーボード向けに ←↓→ などの省略形でも出る。コマンドごとに入力できる時間を指定でき(windowFrames、叩きつけは26フレーム)、長いコマンドでも出しやすくしてある。
  • 動作:相手をつかむ → 持ち上げる(lift)→ 地面に叩きつける。ダメージ22(通常の投げは12)、ダウンを奪い、画面が揺れる。ガード中の相手にも成立。
  • 距離:届く距離は52px(通常の投げは32)。相手が needClose(72px)より遠いときはコマンドが成立せず、他の技(波動拳など)が出る。届く距離と needClose の間は空振りになり、約0.5秒の大きな隙ができる。
  • 通常の投げとの違い:通常の投げは「パンチ+キック同時押し」で全キャラ共通、叩きつけは「キャラ特有の必殺技」として characters.config.js の specials に割り当てる。
  • コマンドの優先:←↓→ は波動拳の ↓→ を含むため、specials では叩きつけを波動拳より前に置く(相手が近いときだけ叩きつけになる)。
  • CPU:近距離で throw の確率でコマンド投げを狙う。
  • 技データの新項目:needClose、lift/liftStart、whiffFrames、poseAt(投げのポーズ切り替えフレーム)。

11b.3 必殺技ゲージと超必殺技「スターブラスト」(superfireball)

ゲージ(設定は game.config.js の meter) - 最大200(100ごとに1本、表示は画面下の左右)。本数を数字でも表示。満タンで点滅。 - たまる量:技を当てたとき=ダメージ×2.0(攻撃側)、ガードされたとき=ダメージ×1.0(攻撃側)、攻撃を受けたとき=ダメージ×1.0(受けた側。ガード時は半分)。 - 通常の投げ・叩きつけ・飛び道具・通常技のすべて、攻撃の判定(ヒット/ガード)を元にたまる。超必殺技自体ではたまらない(noMeter)。 - ラウンドをまたいで持ち越し、試合開始で0に戻る。

超必殺技 - 入力:↓↘→↓↘→+パンチ(キーボード向けに ↓→↓→ でも可)。ゲージ100(cost)を消費。足りないと出ない(通常の波動拳になる)。 - 性能:出始め14フレーム無敵、大きな飛び道具(ダメージ34、ダウン)。ガードされてもダメージの2割を削る(chip、体力は残る)。普通の飛び道具には勝って突き進む(big)。 - 発動演出:世界が40フレーム止まり、画面が暗くなって技名の帯(プレイヤー色)が流れる。設定は superFlashFrames。 - CPU:ゲージがあるとき super の確率で狙う(ai.config.js)。 - 注意:↓↘→↓↘→ の後半に昇龍拳のコマンド(→↓↘)が含まれるため、ゲージ不足で入力すると昇竜拳が出ることがある。

合図の表示:ゲージが1本たまると、ゲージが白く点滅して音が鳴る(約0.6秒)。満タン中は点滅し続ける。

キャラ別の超必殺技:技データの cost がゲージ消費量、title が演出の名前。characters.config.js の specials に割り当てるだけで、キャラごとに別の超必殺技を持たせられる。

11b.4 投げ抜けとため完了の表示

  • 投げ抜け:投げられた側が、つかまれてから techFrames(通常の投げは11フレーム、投げが決まる hitFrame の12フレームより前)以内にパンチ+キック同時押しをすると、ダメージなしで両者が弾かれる(14フレームののけぞり)。技データに techFrames が無い技(叩きつけなど)は抜けられない。同時に投げようとした場合も、先に動いた側の投げを後の側が抜ける形になる。
  • CPU:投げられると、ai.config.js の tech(確率)と techDelay(気づくまでの遅れ)に従って抜けを狙う(EASY=20%、NORMAL=50%)。
  • ため完了の表示:ため技のため(後ろ・下)が chargeFrames を超えると、頭の上に小さな印が出て点滅し、小さな合図音が鳴る。印の色はため技ごとに違う(ソニックブーム風=黄、サマーソルト風=橙)。解放の方向を入れると消える。
  • 通常の投げは、つかまれてから投げ飛ばすまでを8→12フレームに延ばし、抜けの反応が間に合うようにした。

11b.5 高解像度描画(pixelScale 4)

js/config/display.config.js の pixelScale を4にし、キャラだけでなく描くものすべてを同じ細かさにそろえた(キャンバスは 384×224 の4倍 = 1536×896。座標・判定は従来の論理単位のまま)。

対象 対応
キャラ 1ポーズ・1コマ・1配色ごとに一度だけ作って保存。輪郭の太さは max(1, round(pixelScale/2)) 回の縁取りで保つ。起動時に Sprites.preload() で先に作る
背景 W×pixelScale で生成。グラデーション帯・星・月・ビル(縁の光・窓)・もや・路面
文字 3×5の字形を2回のScale2x補間でなめらかにし、キャンバスの1ドットの境目にそろえて描く
エフェクト 火花は細かい1マスずつの star()、画面揺れは1/pixelScale 単位に丸める
UI 体力・ゲージは行ごとのグラデーション、三角マーカーも細かく
影・飛び道具 細かい1マスごとの楕円で描く
表示 ウィンドウに収まる倍率に縮小(小数倍も可)。整数倍のときだけドットをくっきり表示、それ以外はなめらかに縮小

測定(ヘッドレス): 60fps、描画の平均約2ms。ps 2/3/4/6 の比較画像で見た目を確認した。pixelScale を変えるだけで切り替わるが、6以上は描画準備が重くなる。

11b.6 写真をもとにしたキャラ「NAKAGAWA」とキャラ選択

  • 写真(ワイシャツ・濃紺のネクタイ・黒いスラックス・黒いベルト・眼鏡・短い黒髪)から、見た目の特徴だけを取り出してドット絵風に描いた。写真そのものは使っていない。
  • 見た目の種類は Game.Data.Looks(data/palettes.js)に置く。style が体の描き方(karate = 道着、shirt = ワイシャツ姿)、palettes が1P色・2P色。characters.config.js の sprite で選ぶ。
  • sprites.js に shirt 用のパーツ(スラックスの脚と革靴、長袖と袖口、ベルトとバックル、襟とネクタイ、眼鏡と短髪の頭)を追加。ポーズ(関節位置)はヒーローと共通。画像はキャラ・ポーズ・コマ・配色ごとに1回だけ作ってキャッシュする。
  • 技は今のところヒーローと同じ(キャラ固有の技は今後)。
  • キャラ選択はタイトル画面の中に追加した(stage: 'chars')。VS 2P は1P→2Pの順に選び、VS CPU は1Pだけ選ぶ(CPUは別のキャラになる)。上下キーで選び、パンチ(またはEnter)で決定、キックで戻る。

11b.7 判定の精度(コマごとの喰らい判定・キャンセル・コンボ補正・気絶)

設定は js/config/combat.config.js。

項目 内容
コマごとの喰らい判定 ポーズの関節位置から、頭・胴・脚2本・腕2本の箱を毎フレーム作る(Combat.hurtRects)。しゃがむと高い技をかわせ、技を出した腕や脚は伸びた分だけ食らう。frameHurtboxes: false で従来の「体全体で1つの箱」に戻せる。Hキーで箱を表示して確認できる
攻撃判定の切り替え 技の hitbox に [{ t, x, y, w, h }, ...] と書くと、判定が出てから t フレーム目以降は箱が切り替わる(例:立ちキックは3フレーム目から遠くまで届く)
キャンセル 技に cancel: 'special'(必殺技・超必殺技へ)または 'super'(超必殺技のみ)を書くと、当てた(ガードされた)あとの硬直を、必殺技の入力で打ち切って出せる。空振りではキャンセルできない。通常技は special、飛び道具・昇竜などの必殺技は super。コマンド投げへはキャンセルできない
コンボ補正 続けて当たるほどダメージが減る(comboScale。1発目から 1, 1, 0.9, 0.8, 0.7, 0.6, 0.5, 0.4)。のけぞり・ダウンから抜けるとコンボは終わる。2発以上でコンボ数と合計ダメージを画面端に表示
気絶 受けたダメージ(補正後)×1.5 が気絶値にたまり、80でのけぞり・起き上がり後に目を回す(約2.5秒、動けない)。パンチ・キックの連打で短くなる(最低約0.8秒)。90フレーム攻撃を受けないと気絶値が減り始める。ガードではたまらない

確認:判定の組み合わせは、立ちの相手に当たる・しゃがみの相手にはパンチがかわされる・当てたあとだけキャンセルできる・補正が 8,8,7,6,6,5 と減る・気絶して連打で短くなる、をテストで確認した。

11b.8 絵の差し替え口(スプライトシート)

画像(PNG)の絵を、自動生成の絵と同じように使えるようにした。手描きの絵に差し替えるための土台。

  • 見た目の種類に style: 'sheet' を追加(js/data/palettes.js の Game.Data.Looks)。切り出し定義は assets/<名前>.data.js が Game.Data.Sheets に登録する(file:// で動かすため JSON は fetch せず、スクリプトで読む)。
  • 切り出し定義:コマごとの x, y, w, h(画像内の範囲)と ox, oy(足元の位置)、artScale(絵の1ドットがゲームの何分の1単位か)、任意で hurt(コマごとの喰らい判定)。ポーズが足りない・画像が読めないときは fallback の自動生成の絵になる。
  • 絵はゲームの細かさ(pixelScale)に合わせて、ドットをぼかさず拡大して使う(Sprites.get が画像を作ってキャッシュ)。画像の読み込みが終わってからゲームを始める(main.js)。
  • 道具:tools/export_sheet.py(自動生成の絵を画像に書き出す。見本 hero_sheet はこれで作った)、tools/aseprite_to_sheet.py(Aseprite の書き出しを変換)。手順とポーズ名の一覧は assets/README.md。
  • 選択画面に、見本のキャラ「HERO SHEET」を足した(画像で動くことの確認用。不要なら設定から消してよい)。

11b.9 動きの滑らかさ(中間コマ)と画像の切り詰め

  • ポーズとポーズの間を、関節位置の補間で作った中間コマで埋める(display.config.js の anim.tweenSteps、3 = 間を3段階。1で中間なし)。Fighter.pose() が小数のコマ番号を返し、Sprites.get がそれに合う画像を作ってキャッシュする。
  • 技の動き:発生までは「ゆっくり入って速く伸びる」(溜め)、攻撃中は伸びきった姿勢を保ち、硬直は前半で素早く戻って後半は止まる。歩き・待機・気絶も細かく動く。
  • 喰らい判定も中間コマの関節から作るので、動きの途中の腕や脚の位置がそのまま判定に反映される。
  • 画像は絵のある範囲だけに切り詰めて持つ(1枚あたりのメモリが約6割減。立ち絵で 256×256 → 120×215 の例)。足元の位置は画像ごとに originX / originY で持つ。
  • 起動時は整数コマだけ先に作り、中間コマは開始後に少しずつ作る(Sprites.warm、1回約6ms)。間に合わないコマは使うときに作られる。
  • 画像(スプライトシート)の見た目は中間コマを持たず、手描きのコマをそのまま出す。

11b.10 背景の多層化とアニメーション

  • 背景を、空・遠いビル・近いビル・地面の層に分けて作る(render/background.js)。戦っている2人の中間の位置に応じて、奥の層ほど小さく、手前ほど大きくずれる(視差。地面は動かない)。設定は display.config.js の stage(parallax = ずれる量、animate: false で動きを止める)。
  • 動くもの:またたく星、点滅する窓、ゆっくり流れる雲、柵の向こうでゆれる観客(ときどき手を上げる)。
  • 測定(ヘッドレス):描画の平均約1ms、60fps。

11b.11 ポーズごとの絵の描き分け

関節を動かしただけの同じ絵に見えないよう、ポーズ(コマ)ごとに顔・手・効果を描き分けるようにした(js/data/sprites.js の DETAIL 表)。

  • 表情:普通 / 気合い(攻撃の当たる瞬間。吊り眉・細めた目・開いた口)/ 食いしばり(昇竜・ガード・投げの組み付き)/ 集中(構え・戻り)/ 苦悶(やられ。><の目・八の字眉)/ 目を回す(気絶。渦巻きの目)/ 閉じた目(ダウン)。道着・ワイシャツの両方の顔に効く(drawFace)。
  • 手:波動・投げ・叩きつけ・やられ・気絶・ダウンは、握りこぶしでなく指を開いた手にした(openHand)。
  • 効果(輪郭線のあとに白で重ねる。R.late):パンチ/キックの軌跡、昇竜の上昇線、サマーソルトの三日月、波動の気の光とため、投げの力線、叩きつけの地面の衝撃、被弾の衝撃マークと汗、ダウンの土ぼこり。
  • 書き方:DETAIL[ポーズ名][コマ番号] = { f: 表情, oF/oB: 手を開く, fx: [効果名...] }。省略したコマは普通の顔・握りこぶし・効果なし。中間コマは近いほうのコマの描き分けを使う。
  • 描画の重さは変わらない(測定は従来と同等)。見た目はキャッシュされ、描き分けはコマごとに1回だけ作る。

11b.12 キャラ固有の技

技ライブラリ(moves.config.js)にキャラ専用の技を足し、characters.config.js の specials で技を振り分けた。

  • HERO:波動(↓↘→+P)・昇竜(→↓↘+P)・STAR BLAST(超必殺)の「基本の型」。ため技と叩きつけは持たない。
  • NAKAGAWA:ため技と投げ中心。書類ばらまき(←ため→+P。速くて軽い)・カバン投げ(↓↘→+P。遅くて重い)・ヒールキック(↓ため↑+K。威力+1)・叩きつけ(半回転+P)・超必殺 OVERTIME(書類の嵐)。足は遅め(walkSpeed 1.35)・ジャンプは低め、立ちパンチのリーチが長い。
  • 飛び道具の見た目は projectile.look('paper' = 紙 / 'case' = カバン。省略は気の玉)で選ぶ(renderer.js の drawThrown)。
  • CPUは、持っている技の種類(飛び道具・対空・投げ・超必殺)から自動で選ぶので、キャラごとの技でもそのまま動く。
  • 新しい技のポーズは、既存ポーズを pose で使い回す(専用ポーズは今後)。

11b.13 新技の専用ポーズ

NAKAGAWA の新技に、波動の使い回しではなく専用のポーズ(各3コマ:構え → 放つ → 戻り)を付けた(sprites.js)。

  • paperToss(書類ばらまき):書類の束を体の前へ引く → 横に振り抜く(開いた手と軌跡)。
  • briefcase(カバン投げ):カバンを頭の後ろへ振りかぶる → 体ごと前へ投げ出す → 前かがみで残心。
  • overtime(OVERTIME):書類を腰の後ろへ溜める → 両腕を大きく広げて書類を撒き散らす → 前へ突き出す。
  • 技側は moves.config.js の pose で指定。持ち物(カバン・書類の束・舞う書類)は DETAIL の効果 caseHeld / paperHeld / papers で重ねて描く。
  • 配色に c / C(カバンの茶色と影)を追加(palettes.js、全配色)。

11b.14 写真から作るステージ(池袋の喫煙所前)

  • 写真をドット絵風の背景画像にして使うステージを追加した。tools/make_stage.py 写真.png assets/stage_xxx.png で作る(412:224 に切り出し → 824×448 に縮小 → 48色に減色)。画像は左右に余白 14 を持ち、戦っている2人に合わせて少しだけ横にずれる(視差)。
  • 設定:display.config.js の stage.list(ステージ名 → 画像・視差量)と stage.id(使うステージ)。night は従来の自動生成の夜の街。
  • 対戦中・タイトル中に B キーでステージを切り替えられる(renderer.js)。画像を読み込めない間は夜の街を出す。
  • 写真には通行人(ぼかし済み)が写っている。ドット絵化でさらに判別できなくなるが、左下の傘の人物はキャラと重なりやすい。必要なら写真側で人物を消してから変換する(単純な自動補完は不自然になったので採用しなかった)。

11b.15 デフォルメしたステージ「駅前の喫煙所」

11b.19 画面遷移をストリートファイター2風に(タイトル → キャラ選択 → VS画面)

画面の流れを タイトル(PRESS START)→ メニュー(1 PLAYER / VS BATTLE)→(CPU強さ)→ キャラ選択 → VS画面 → 対戦 → 結果(REMATCH / CHARACTER SELECT / TITLE) にした。

  • タイトル(ui.js の drawTitle):押し出しロゴ(影を重ねた厚み)と、横切る光の帯、点滅する PRESS START BUTTON。背景は選ばれているステージ。
  • キャラ選択(scenes/select.js):中央に顔のアイコン(4×8枠、未実装の枠は「?」)、左右に1P(赤)・2P(青)の上半身と名前・肩書き、上にステージの予告(いま見ているキャラのステージを縮小して実際の背景で表示)。2P対戦は両者が同時に選ぶ。1人用は1Pが決めるとCPU側がルーレットで切り替わって決まる。キックで取り消し、誰も決めていなければタイトルへ。
  • VS画面(scenes/versus.js):左右の色の斜め面に、2人の上半身が滑り込み、中央に VS、下に名前、上にステージ名。約2.5秒、パンチ/スタートで飛ばせる。
  • ステージはキャラごと(characters.config.js の stage。対戦の舞台は1Pのキャラで決まる)。肩書きは tag。顔と上半身の絵は待機ポーズの切り出し(render/portrait.js。専用の絵を作らなくてもキャラを足せば出る)。
  • 対戦の結果メニューに「CHARACTER SELECT」を追加。文字(フォント)に「?」と「/」を追加。
  • 遷移の部品:Renderer.draw は、シーンが drawScreen(ctx) を持っていればその画面を丸ごと描く(選択・VS画面はこれ)。Renderer.setStage(id) / backgroundOf(id) で背景を指定できる。

11b.20 ステージのランダム化と、サンプルキャラ5人の追加(選択画面の8枠を埋める)

  • ステージはキャラ固有ではなくランダム:scenes/select.js が画面に入るたびに display.config.js の stage.list から1つ選び(this.stageId)、予告表示・VS画面・対戦で同じものを使う。characters.config.js の stage は使われない(残してあるだけ)。
  • 汎用の人物 style: 'casual'(sprites.js の paintCasual):palettes.js の look に opts を書くだけで見た目を作れる。
  • hair: short / spiky / buzz / bald / long / pony / bun / buns / afro
  • top: long / tee / tank / bare / dress　bottom: pants / shorts / skirt / none
  • thick(体の太さ。1.28=大柄、0.9=細身)、beard、band、gloves、glasses、lips、mark
  • 色は2色セット(1P/2P)。共通の色は base() が補うので、変えたい色だけ書く。奥側の手足を暗くする対応表は sprites.js の DARK。
  • 仮キャラ5人(技は既存の技ライブラリの組み合わせ。数値は仮):MEI(中国・女性・小柄で素早い)、BORIS(ロシア・男性・大柄で投げが強い)、ISA(ブラジル・女性・蹴り中心)、JAX(アメリカ・男性・ボクサー)、PRIYA(インド・女性・投げと飛び道具)。characters.config.js の order で8人。
  • 選択画面のHERO SHEETの顔アイコンが小さい問題を直した(portrait.js の sheetFace。file:// では画素を読めないので、足元の位置からの目安で切り出す)。

11b.21 ダッシュとバックステップ

  • 前を素早く2回押す(physics.config.js の dashTapFrames = 14フレーム以内)とダッシュ。2回目を押し続けるあいだ走り続け(dashSpeed 3.4)、離すと止まる(最短 dashMinFrames 8フレームは走る)。ダッシュ中にパンチ/キック/ジャンプ/投げに移れる。しゃがむとやめる。
  • 後ろを素早く2回押すとバックステップ(backstepFrames 18、初速 backstepSpeed 3.6、少し浮く backstepHop 7)。動き出したら止まれず、ガードも投げられもしない状態になるが、攻撃は受ける。
  • 実装は fighter.js:detectDoubleTap(押した瞬間の間隔を見る)と、状態 dash / backstep。値は physics.config.js(キャラごとに body で上書き可)。絵は歩きのポーズを速く回す/ジャンプのポーズ(専用ポーズは未作成)。
